# Camera cards: design

- Library: verify before adding (package exists, size, license, maintenance). Prefer a small ArUco library loaded with dynamic `import()`. Record the decision in `docs/decision-log.md`. If none is suitable, write the blocker and keep the pure logic and tests.
- `src/camera/presence.ts` (pure): `createDebouncer({ presentFrames, absentFrames })` with `push(detectedIds: number[]) => Signal[]`. Frame-count based, so no timers. Defaults: `presentFrames` 3, `absentFrames` 5.
- `src/camera/markers.ts`: fixed map `markerId -> ComponentId` for four ids.
- `src/camera/mapping.ts` (pure): `signalToCommand(signal): Command`. Imports only the `Command` type.
- `src/camera/adapter.ts`: owns `getUserMedia`, a video element, the frame loop (`requestAnimationFrame`) and the detector. Feeds detections to the debouncer and calls `onSignal`. No simulation import.
- `src/camera/CameraPanel.tsx`: start button, status text, errors (denied, none, unsupported), link to Digital Lab. Loaded lazily from the lab only when `mode=physical`, and the adapter only after the click.
- Cards: `public/cards/` SVG per component plus `public/cards/index.html` print sheet, generated by a script from the library dictionary.
- Tests (no hardware): debouncer with fake frame sequences, mapper, marker table, an import-boundary test that fails if `src/camera` imports `src/simulation` runtime code, and an E2E that `/lab?mode=digital` and `/` make no camera request and never call `getUserMedia` (stubbed with a counter).
