# Specs to create *through Kiro's actual Spec workflow*

Create these after inspecting codebase; keep requirements.md, design.md, tasks.md in each:

- `core-simulation/`: state machine, events, recovery, idempotency, replay and property tests.
- `digital-lab/`: usable camera-free architecture UI, controls, guided lesson and timeline.
- `camera-cards/`: fixed four-marker recognition, debounce, permission UI, fallback.
- `portal-experience/`: Halloween sci-fi landing, portal transition, mobile/accessibility/performance.
- `judge-readiness/`: deployment, browser QA, evidence capture and demo acceptance.

Do not create spec files purely to satisfy the folder structure. Generate via Kiro, review and revise, and link completed tasks to commits/tests.
