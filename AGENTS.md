# PaperFault agent guidance

- Project: PaperFault, a Halloween-themed interactive lab for learning distributed-system failure and recovery.
- Submit to Kiroween 2026 as a new project; preserve genuine provenance and Kiro evidence.
- Prioritize a functioning product, polished UX, and an unforgettable physical-card demo over feature count.
- Core simulation: deterministic, pure TypeScript, separate from React and computer-vision input.
- Every simulation state displayed must derive from real simulation transitions; no fake success or failure animations.
- Use the native Kiro spec workflow and keep `.kiro/specs` current.
- Keep `.kiro/` checked into Git and not ignored; never save secrets there.
- Respect reduced motion, keyboard access, camera privacy, and slow-network performance.
- Do not invent measurements, bugs, MCP invocations, hooks executed, or Kiro feature usage; log verified evidence only.
- No scope expansion unless it improves one of five judging dimensions without imperiling completion.
