# Architecture and design decisions

| Date | Decision | Alternatives considered | Reason | Kiro assistance | Tests and trade-offs |
|---|---|---|---|---|---|
| 2026-11-24 | Prefer deterministic TypeScript simulation independent from UI | React-driven state/timeout simulation | Easier deterministic replay/property testing | Starter planning only; not an execution claim | To validate |
| 2026-11-24 | Digital Lab must work without webcam | Camera-only product | Ensures judges can test it | Starter planning only | To validate |
| 2026-11-25 | Core-simulation spec fixes before coding: `TICK` has no payload (requirements said it carried a tick number, design said it did not); state changes only via `applyEvent`, so `replayEvents` is exact by construction; `createState()` takes no config; queue-down submit is rejected; duplicate submit id is suppressed; parked orders requeue when the database comes back; worker-down requeues the in-flight order | Keeping tick number in the command; storing config in state | Resolves a requirements/design contradiction and fills behaviour gaps the tasks would otherwise leave undefined | Web agent edit of `.kiro/specs/core-simulation/` | Covered by unit tests and properties, see `docs/kiro-usage.md` |
| 2026-11-25 | Use `js-aruco2` 2.0.0 (runtime dependency) for ArUco detection and for generating the printable cards. Load it only by dynamic `import()` after the camera start click. Use the built-in `ARUCO` dictionary (7x7 marker, 25 bit payload, 1023 codes, min hamming distance 3) with ids 0 to 3 | Hand-written detector (too much work and risk); `js-aruco` (original, older, no custom dictionary or SVG generation); OpenCV.js (several MB); `ARUCO_MIP_36h12` (more robust but only 250 codes and 8x8 grid needs larger print) | Verified on 2026-11-25 with `npm view` and a GitHub API call: package exists, single published version 2.0.0 (modified 2025-06-19), MIT in `package.json` and `LICENSE.txt` (GitHub reports NOASSERTION because the file also carries the js-aruco copyright), unpacked 424 KB of which `src/aruco.js` is 26 KB and `src/cv.js` is 17 KB (dictionaries are separate files), no dependencies, repository not archived, last GitHub push 2023-08-10, 88 stars. Maintenance is light, so the pure presence and mapping logic is kept independent of the library behind a small detector interface and can swap libraries. The package is CommonJS and sets `this.AR`; `require` returns `{ AR }`. Whether Vite's bundler keeps that shape is checked by a build and a unit test | None (web agent decision) | Detection accuracy on a real camera is NOT verified. Trade-off: hamming distance 3 allows few bit errors, so print cards large and well lit |
| 2026-11-25 | Add a small Vite plugin (`js-aruco2-exports` in `vite.config.ts`) that rewrites three lines of `js-aruco2` (`this.CV = CV`, `this.CV \|\| require(...)`, `this.AR = AR`) to use `exports` | Importing the package unmodified; vendoring a patched copy; writing a detector | The bundler turns the package's top-level `this` into `undefined`, so `AR` was missing from the production chunk. This was found by `e2e/camera.spec.ts` (detector failed to load) and fixed. Production build and preview only: the Vite dev server (`npm run dev`) was not tried | None (web agent decision) | If `js-aruco2` changes those lines the plugin silently does nothing and the E2E fails |
